# Калькулятор урона — все классы и расы (наша редакция ДнД)

Дата: 2026-06-28
Статус: дизайн утверждён, готов к плану реализации
Развивает: `2026-06-27-dmg-calculator-design.md` (орк-волшебник)

## Цель

Превратить текущий калькулятор (заточен под орка-волшебника) в полноценный
инструмент, покрывающий **все 12 классов и 11 рас** нашей редакции и их
урон-способности. Главное требование — **расширяемая архитектура**: добавление
нового класса или расы не требует переделки движка, пайплайна и UI.

## Форм-фактор (без изменений)

Один самодостаточный файл `dnd-dmg.html` (HTML+CSS+JS инлайн, без интернета и
зависимостей). Открывается двойным кликом, в т.ч. на телефоне. Сборка через
`build.js` (склейка модулей + Web Worker из Blob). Движок — Монте-Карло, 100 000
прогонов, детерминированное зерно.

**Сохранение состояния:** вся сборка формы (герой, выбранная способность и её
параметры, модификаторы, список целей) сохраняется в `localStorage` и
восстанавливается при переоткрытии страницы. Кнопка **«Сбросить»** одним нажатием
очищает состояние и возвращает форму к значениям по умолчанию.

## Ключевые решения (зафиксированы с заказчиком)

1. **Объём v1:** архитектура + урон-способности всех 12 классов сразу.
2. **Полная сборка героя:** выбор класс + раса + «игра» (уровень 1–20) →
   автоматический вывод 6 характеристик, куба оружия с владением, доступных
   способностей, выбора способности 12-й игры, таланта, пассивных артефактов.
3. **Типы урона полностью** + расовые правила цели (сопротивления/уязвимости) +
   зелья по категории урона.
4. **Единица расчёта = одна способность.** Мультиатаки самодостаточны
   (Град ударов = 4 атаки внутри). Доп. атака / «два действия» — тумблеры.
5. **В калькулятор попадают** способности, наносящие урон, и модификаторы урона.
   Чистое лечение / контроль без урона / призыв питомцев / утилити — вне рамок.
6. **Артефакты — только пассивные**, влияющие на атаку/урон/крит. Активируемые
   и «раз в день/бой» — вне рамок.

## Архитектура: слои и файлы

Расширяем нынешние 3 слоя. Способности дробятся по классам для расширяемости.

```
src/
  engine.js        — кубы, броски, преимущество/помеха, крит (critRange)
  types.js         — типы урона и их категории (НОВОЕ)
  characters.js    — CLASSES, RACES, прокачка, вывод статов героя и пресетов целей
  abilities/
    index.js       — сбор всех способностей в плоский ABILITIES (НОВОЕ)
    warrior.js, barbarian.js, ... wizard.js  — по файлу на класс (НОВОЕ)
  modifiers.js     — пайплайн расчёта урона (НОВОЕ; вынесено из simulator)
  simulator.js     — Монте-Карло агрегация метрик
  ui.js            — интерфейс
```

`build.js` склеивает `src/abilities/*.js` автоматически (glob), чтобы добавление
класса = добавление одного файла + строки в `CLASSES`. Движок/пайплайн/UI не
трогаются.

**Принцип границ:** способность знает только свою базу (какие кубы катит, какой
стат прибавляет владение, какие у неё параметры). Всё остальное — модификаторы,
зелья, расовые правила цели, крит — живёт в `modifiers.js` и применяется
единообразно ко всем способностям.

## Модель персонажа-атакующего

```js
character = {
  classKey, raceKey, game,                 // game = 1..20 («игра»/уровень)
  stats:  { str, dex, con, wis, int, cha },// выведены, можно править вручную
  weapon: { dice: '1d10', stat: 'str' },   // куб и стат владения (из класса)
  game12Choice: abilityId | null,          // выбор одной из двух способностей 12-й
  artifacts: [ 'runeOfWarrior', ... ],     // только пассивные
}
```

Владение оружием не хранится флагом: моделируется штатное оружие класса, поэтому
стат оружия (`weapon.stat`) всегда прибавляется к атаке и урону. Талант 16-й игры
не хранится в персонаже — его наличие выводится из `game ≥ 16`, а применение его
`+3` к броску — опциональный модификатор-тумблер (см. «Модификаторы»).

### Вывод характеристик

`stat = базовый_класса + расовая_правка + приросты_по_играм`.

Прокачка из правил:
- 4/8/12/16/20 игра — `+5` к HP (влияет на пресеты целей, не на исходящий урон).
- **8-я игра** — `+1` к двум разным характеристикам. По умолчанию две наивысшие;
  пользователь может переопределить вручную.
- 16-я игра — талант (доступен автоматически; применяется как модификатор-тумблер).
- 20-я и далее — артефакт (выбор пассивного).

Любой выведенный стат правится вручную (как сейчас AC/HP целей).

`CLASSES` расширяется до полной таблицы из правил: 6 статов, куб оружия, стат
владения. `RACES` дополняется флагами пассивок атакующего (напр. `orcReroll`) и
правилами цели (`onIncoming`, см. раздел про типы урона).

## Типы урона

```js
// types.js
TYPES = {
  physical:  { cat: 'physical' },
  magic:     { cat: 'magic' },
  fire:      { cat: 'magic' },
  lightning: { cat: 'magic' },
  necrotic:  { cat: 'magic' },
  psychic:   { cat: 'magic' },
  radiant:   { cat: 'magic' },
}
```

Категория (`physical` / `magic`) — то, на что смотрят зелья и расовые правила
цели:
- Зелье ярости — `×2` урона категории `physical`.
- Зелье хаоса — `×2` урона категории `magic`.
- Орк (цель) — `+2` к получаемому урону категории `magic`.
- Аасимар (цель) — `+2` к получаемому урону категории `physical`.
- Дварф (цель) — сопротивление `×0.5` урону категории `magic`.

Конкретный подтип (`fire`/`lightning`/…) хранится для отображения (цвет свечения
по типу) и под будущие точечные правила.

## Контракт способности

```js
ABILITY = {
  id, name, classKey,
  minGame: 1 | 4 | 12,          // когда становится доступна по прокачке
  choiceGroup: 'game12' | null, // если это одна из двух способностей выбора 12-й
  charges: 'текст',             // отображение расхода (3 раза в бой и т.п.)
  targeting: 'single' | 'area' | 'chain',
  params: [ /* см. ниже */ ],   // ability-specific входы (по умолчанию [])
  simulateOnce(ctx) -> targets.map(t => [ {type, amount}, ... ]),
}
```

`simulateOnce` возвращает на каждую цель **список типизированных пакетов урона**
(не плоское число). Это нужно, чтобы зелья/сопротивления работали по типу, а
модификаторы (кара, скрытная атака) добавляли урон *другого* типа поверх оружия.

`ctx` даёт способности: `stats`, `weaponDie`, `attackBonus(stat)`, `rng`,
`critRange`, `mods` (тумблеры), `params` (значения её параметров), `targets`.

## Параметры способности (ability-specific входы)

Декларативный механизм: способность сама описывает нужные входы, UI авто-рендерит
контрол по `kind`, значения приходят в `ctx.params[id]`. Это убирает спец-поля из
`ctx` (нынешние `chainSeq`, `targetDexSave`) и делает «особенную» способность
самодостаточной.

```js
ABILITY.params = [ { id, kind, label, default, ...опции } ]
```

| kind | назначение | примеры |
|------|------------|---------|
| `targetPick`  | выбрать одну цель | любая одноцелевая атака |
| `targetOrder` | упорядоченное подмножество целей | Цепная молния, Путь в небытие, Жатва |
| `distribute`  | разложить N попаданий/снарядов по целям | Волшебные снаряды (3), Град ударов (4) |
| `select`      | выбор из вариантов | Аргумент (наконечник), Облик зверя (медведь/змея) |
| `stepper`     | целое число | Бож. кара (сколько д10), переменные атаки |
| `toggle`      | локальный флаг способности | Скрытная атака (из скрытности / ×2) |

**Дефолты обязательны:** каждый параметр имеет разумное значение по умолчанию,
чтобы способность считалась без ручного ввода (цепь — жадно по наим. AC;
распределение — по кругу; кара — максимум доступных кубов; цель — первая).

**Случайные эффекты** (Погребальный звон д20→тир, Нестабильный аргумент д4,
настойка барда д4) параметров не требуют — катятся внутри `simulateOnce`,
Монте-Карло усредняет распределение.

Настойку барда можно дать и союзнику, но калькулятор считает *исходящий урон
самого героя*, поэтому моделируем её только когда её пьёт сам атакующий (тогда
случайный бафф д4, включая «смелость варвара» ×2, влияет на его урон); применение
на других персонажей — вне рамок.

**Многоходовые эффекты** (Друид-змея «тот же урон 2 следующих хода») в v1 считаем
только немедленный удар; DoT помечаем текстом.

## Пайплайн расчёта урона (порядок операций)

Живёт в `modifiers.js`. На каждый прогон, для каждой цели:

1. **База.** Способность катит кубы в типизированные пакеты (владение добавляет
   стат к атаке/урону там, где способность это объявляет).
2. **Аддитивные модификаторы атакующего** добавляют пакеты: концентрация `+2д6`,
   бож. кара `+Nд10`, скрытная атака, талант `+3` к кубу, руна воителя `+1`.
3. **Множители атакующего** по категории (после аддитивных того же типа):
   зелье ярости `×2` physical, зелье хаоса `×2` magic.
4. **Правила цели** по категории: сначала уязвимость (`+2`), затем сопротивление
   (`×0.5`, floor). У расы применяется не более одного правила. Если раса цели не
   задана (уникальный противник) — правила не применяются.
5. **Крит/попадание:** натуральная `≥ critRange` (20 по умолчанию; 19 — Наручи
   удачи; 18–20 — «Слабое место») = авто-попадание. Удвоение кубов на крите
   остаётся выключенным (`CRIT_DOUBLES_DICE = false`, как сейчас).

После пайплайна пакеты суммируются в число на цель → метрики/гистограмма.

## Инвентарь урон-способностей по классам

Каждый класс дополнительно получает generic **«Базовая атака оружием»** (куб
оружия + стат владения). А = способность; М = модификатор-тумблер;
`[12]` = одна из способностей выбора 12-й игры.

| Класс | Способности (А) | Модификаторы (М) |
|---|---|---|
| **Воин** | Град ударов (4 атаки, `distribute`) | Воинское мастерство (+атака), Слабое место `[12]` (крит 18–20) |
| **Варвар** | Танец со смертью (area, спас Лов-12) | Ярость (Сила×2), Мастер большого оружия `[12]` (−5 поп / +10 урон) |
| **Плут** | — (база 2д4) | Скрытная атака (`toggle` из скрытности, ×2), Фартовый `[12]` (промах→крит) |
| **Паладин** | — | Бож. кара (`stepper` Nд10, излучение), Доп. атака `[12]`, Улучш. кара `[12]` (макс 6д10) |
| **Друид** | Облик зверя (`select` медведь/змея), Тернистый путь (area 3д6) | Ярость зверя `[12]` (кубы форм↑) |
| **Волшебник** | Волш. снаряды, Цепная молния, Огненный шар, Телекинез, Неизвестная атака `[12]` (15) | Сглаз (помеха спасу цели), Концентрация (`stepper` 2д6) |
| **Изобретатель** | Аргумент (`select` наконечник), Нестабильный аргумент `[12]` (d4-эффект) | Стрельба от бедра (2 выстрела помеха), Прицельный выстрел (преим.), Весомый аргумент `[12]` (расширяет наконечники) |
| **Жрец** | Божественный свет `[12]` (area 1д4+Ст) | Священное оружие (+Ст к атаке/урону) |
| **Бард** | — | Улучш. воодушевление (+д6 урон), Настойка «смелость» (×2) |
| **Следопыт** | — (база: Быстрая рука = 2 выстрела) | Чутьё охотника (авто-поп.), Засада (+атака), Охотник на великанов `[12]` (−AC по Муд), Рикошет `[12]` (+цель) |
| **Некромант** | Путь в небытие (`targetOrder` линия, 1д8+Инт), Погребальный звон (d20→тир некро), Жатва `[12]` | — |
| **Монах** | Шквал (N=Стойкость атак) | Бесконтактный бой (тип→маг), Усиление Ци `[12]` (1д6 безоруж.) |

Полные кубы/типы/параметры каждой способности уточняются при реализации из
`Правила Днд.txt`.

**Вне урона (пропускаем):** лечение, чистый контроль/опрокидывание, призыв
нежити/питомцы, телепорт/утилити, ресурсы «раз в день/бой» как механика учёта.

## UI (mobile-first, язык «боевого гримуара»)

Сохраняем существующую дизайн-систему (чернильно-фиолетовый фон, пергамент,
рунное золото). Свечение завязано на тип урона. Утверждено по мокапу.

- **Конструктор героя (новое):** `Класс ▾ / Раса ▾ / Игра ▾` → панель выведенных
  6 статов (редактируемых, ▲ = прирост по играм), куб оружия с владением; при
  доступности — выбор способности 12-й игры, талант, пассивный артефакт.
- **Выбор способности** — только доступные текущему герою (фильтр `minGame` /
  `choiceGroup`); не-урон способности видны приглушённо и помечены «не урон».
- **Параметры способности (новое)** — авто-рендер контролов под селектором
  способности (степпер кары, выбор/порядок целей, наконечник и т.п.).
- **Модификаторы** — релевантные подсвечены, неприменимые приглушены (как
  сейчас); расовые пассивки атакующего (орочий переброс) включаются автоматически.
- **Цели** — пресет по `Раса + Класс + Уровень` (подставляет броню и HP, дальше
  правка вручную) **либо** ручной ввод. **Раса необязательна** — уникальный
  противник (босс/конструкт) задаётся без расы, тогда расовые правила не
  применяются. У целей с расой показывается активное правило (напр. «−50% к маг»).
- **Результат (изменено):** блок **не закреплён по умолчанию**; кнопка
  «📌 Закрепить» делает его липким по желанию.
- **Сохранение/сброс (новое):** состояние формы пишется в `localStorage` и
  восстанавливается при открытии; кнопка «Сбросить» очищает его одним нажатием.
- **Метрики (как сейчас):** ожидаемый урон по цели и по группе, мин/макс,
  гистограмма с медианой/средним/межквартильным размахом, шанс убить за ход,
  шанс ≥ X. Таблица сравнения сравнивает урон-способности **текущего** героя.

## Тестирование (node --test)

- Вывод статов по класс/раса/игра (golden), включая прирост 8-й игры.
- Порядок пайплайна: аддитив → множитель → правила цели.
- Правила цели по категории: дварф ÷2 маг, орк +2 маг, аасимар +2 физ; уникальный
  противник без расы — без правил; зелья по категории.
- По одной «заглавной» урон-способности на класс — golden-среднее на фикс. зерне.
- Дефолты параметров дают валидный прогон без ручного ввода.
- Существующие тесты волшебника мигрируют на новую модель пакетов урона.

## Вне рамок v1 (YAGNI)

- Лечение, чистый контроль, призыв нежити/питомцы, телепорт/утилити.
- Экономика действий за весь ход (composition действие + бонусное + реакция).
- Многоходовой DoT как расчёт (только текстовая пометка).
- Учёт ресурсов «раз в бой/день» как игровая механика.
- Артефакты с активацией и лимитом использования.
